# Google Calendar Source Schema

**Status:** ACTIVE (introduced in AI Project OS v1.6 Google Calendar Live Sync, Gate 1, 2026-05-30)
**Owner:** Coordinator / Project Control
**Purpose:** Defines the repo-native source model for Google Calendar events. Scripts and agents use this schema when generating dry-run output, creating events, and validating source records.
**Companion docs:** `google-calendar-source-records.json`, `google-calendar-sync-policy.md`, `google-calendar-sync-runbook.md`, `external-sync-safety.md`, `external-sync-map.example.json`
**Companion scripts:** `scripts/google-calendar-source-validate.mjs`, `scripts/google-calendar-sync-dry-run.mjs`, `scripts/google-calendar-sync-apply.mjs`, `scripts/generate-project-calendar.mjs`

---

## Source record fields

| Field | Required | Type | Description |
|---|---|---|---|
| `os_id` | Yes | string | Stable AI OS ID (`keepmees-<role>-<slug>`). Never changes once assigned. Primary identity key. Used as `duplicate_key` and embedded in event description. |
| `title` | Yes | string | Google Calendar event title. |
| `description` | Yes | string | Event description. MUST end with `\n\nAI_OS_ID: <os_id>` for duplicate detection. Scripts generate this marker automatically. |
| `calendar_role` | Yes | enum | One of: `ritual`, `phase-gate`, `milestone`, `package-review`, `package-closeout`, `budget-review`, `roadmap-reset` |
| `start` | Yes | ISO 8601 | Start datetime (first occurrence for recurring events). Format: `YYYY-MM-DDTHH:MM:SS`. Timezone applied separately via `timezone` field. |
| `end` | Yes | ISO 8601 | End datetime (first occurrence). Same format as `start`. |
| `timezone` | Yes | string | IANA timezone identifier (e.g. `America/New_York`). Applied to `start` and `end`. |
| `recurrence` | No | RRULE string | RFC 5545 RRULE without the `RRULE:` prefix (e.g. `FREQ=WEEKLY;BYDAY=SU`). Omit for one-time events. |
| `all_day` | No | boolean | Whether the event spans a full day with no time component. Default `false`. |
| `status` | Yes | enum | One of: `active`, `paused`, `archived` |
| `source_file` | Yes | string | Relative path to the repo doc that defines this event. |
| `phase` | No | string | Project phase (e.g. `0`, `5`). |
| `package` | No | string | Associated package (e.g. `Package 5B`) for milestone or closeout events. |
| `owner_role` | No | string | Responsible role (e.g. `Coordinator`, `Founder`). |
| `calendar_relevant` | Yes | boolean | Always `true` for records in this file. |
| `github_project_os_id` | No | string | `os_id` of a linked GitHub Project source record, if one exists. |
| `duplicate_key` | Yes | string | Stable identity marker = `os_id`. Used during dry-run duplicate detection. |
| `notes` | No | string | Non-obvious context: constraints, risks, migration notes, adoption plan. |

## Duplicate prevention markers

Every event managed by v1.6 must carry two identity markers:

### 1. Visible description marker (required)

Embed at the end of the event description (generated by scripts automatically):

```
AI_OS_ID: <os_id>
```

Example:
```
Founder-level direction and capacity check.
...

AI_OS_ID: keepmees-ritual-ceo-review-weekly
```

This marker is visible in the Google Calendar event description UI. It survives event edits if the Coordinator does not remove it.

### 2. extendedProperties.private marker (planned for Gate 3)

When creating events via the Google Calendar API, scripts will also set:

```json
"extendedProperties": {
  "private": {
    "ai_os_id": "<os_id>"
  }
}
```

This marker is not visible in the UI but is preserved by the API and provides a machine-readable identity anchor. Gate 1 scripts include this field in planned event payloads; Gate 3 apply will write it.

## ID stability rule

A stable `os_id` must never change once assigned, even if:
- The event title changes
- The date shifts
- The status changes to `paused` or `archived`
- The event is moved between calendars

If an event is permanently removed, its `os_id` is retired (kept in the local sync map with `status: removed`) and never reused.

## Field routing

### Event created in Google Calendar

| Source field | Google Calendar destination |
|---|---|
| `title` | Event summary |
| `description` (including `AI_OS_ID:` marker) | Event description |
| `start` + `timezone` | Event start (dateTime + timeZone) |
| `end` + `timezone` | Event end (dateTime + timeZone) |
| `recurrence` | Event recurrence (RRULE array) |
| `os_id` | `extendedProperties.private.ai_os_id` (Gate 3) |

### ICS export (fallback)

| Source field | VCALENDAR field |
|---|---|
| `os_id` | `UID: <os_id>@keepmees.local` |
| `title` | `SUMMARY:` |
| `description` | `DESCRIPTION:` |
| `start` + `timezone` | `DTSTART;TZID=<timezone>:` |
| `end` + `timezone` | `DTEND;TZID=<timezone>:` |
| `recurrence` | `RRULE:` |

### Local sync map (gitignored — never committed)

| Field | Stored in `external-sync-map.local.json` |
|---|---|
| Google Calendar event ID | `google_calendar[os_id].external_id` |
| Calendar ID used | `google_calendar[os_id].calendar_id` |
| Last synced date | `google_calendar[os_id].last_synced` |
| Status | `google_calendar[os_id].status` |

## Dry-run classification categories

The dry-run script classifies each source record as one of:

| Classification | Meaning |
|---|---|
| `READY_FOR_LIVE_COMPARE` | Source record is valid; ready for Gate 2 live comparison |
| `INVALID_SOURCE` | Source record fails validation; must be fixed before Gate 2 |
| `CREATE` | (Gate 2+) Event not found in Google Calendar; propose creation |
| `UPDATE` | (Gate 2+) Event found but differs from source record; propose update |
| `NO_OP` | (Gate 2+) Event matches source record exactly |
| `DUPLICATE_DETECTED` | (Gate 2+) Two or more events match the same `AI_OS_ID` marker |
| `ADOPTION_REQUIRED` | (Gate 2+) Existing event found by title/date (no `AI_OS_ID` marker yet) |
| `MISSING_LOCAL_MAPPING` | (Gate 2+) Live event found but not in local sync map |
| `MAPPED_EVENT_MISSING_REMOTELY` | (Gate 2+) Local sync map has event ID but event not in Google Calendar |
| `REMOTE_DRIFT` | (Gate 2+) Live event differs from source and no apply was recorded in sync log |
| `DELETE_CANCEL_CANDIDATE` | (Gate 2+) Source status is `archived`/`paused` but event is active in Google Calendar |
| `NEEDS_MANUAL_REVIEW` | (Gate 2+) Ambiguous match; Coordinator decision required |

## What does NOT belong in source records

Source records must not contain:
- Actual Google Calendar event IDs (belong in `external-sync-map.local.json` only)
- OAuth tokens, client secrets, or credential paths
- Local account identifiers beyond safe `owner_role` text
- Actual `last_synced` timestamps (belong in local sync map or sync log)
- `external_sync_status` as a live field (derived from dry-run, not stored in source records)

## Schema validation

Validated by `scripts/google-calendar-source-validate.mjs`. Run before any Gate 2 or Gate 3 operation.

Validator checks at minimum:
- All required fields present
- `os_id` values unique within the file
- `start` and `end` are valid ISO 8601 datetimes
- `timezone` is a recognized IANA timezone string
- `recurrence` is a valid RRULE string if present
- `calendar_role` is from the approved set
- `status` is from the approved set
- No actual Google Calendar event IDs in any field
- No credential-like strings (token, secret, oauth, credential)
- `AI_OS_ID:` marker derivable from `os_id`
- `calendar_relevant` is `true` for all records
